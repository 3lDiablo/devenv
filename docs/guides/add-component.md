# Deploying a New Component

The architecture is designed to be highly modular. Adding a new component (e.g., Redis, Elasticsearch, or a custom microservice) requires updating a few strategic files to wire it into the SSoT pipeline.

Follow this step-by-step guide to integrate a new service.

## 1. Add Configuration to `config.yaml`

First, define the component's settings and image in the SSoT. For a full reference of available core schema keys, see the [Configuration Schema Reference](../reference/config-schema.md).

Open `config.yaml`:
```yaml
# Add to the settings block
settings:
  new_service:
    port: &new_service_port 8085
    custom_setting: "true"
    resources:
      cpu:
        request: "50m"
        limit: "200m"
      memory:
        request: "128Mi"
        limit: "256Mi"

# Map the port if it needs to be accessed from the host machine
cluster:
  ports:
    - name: new-service
      host: *new_service_port
      node: 30085

# Define the image explicitly
images:
  new_service:
    registry: docker.io
    repository: mycompany/new-service
    tag: "v1.0.0"
```

## 2. Create the Base Manifests & Configuration Templates

Create a new directory for your component under `k8s/components/base/`.

```bash
mkdir -p k8s/components/base/new-service
```

### A. Configuration Template Management
If the component requires a custom configuration file (like **CloudBeaver's** `data-sources.json` or **Redpanda Console's** `console-config.yaml`), create a template file in the base directory (e.g., `config.conf.tpl`):

```conf
# k8s/components/base/new-service/config.conf.tpl
server.port = __SERVICE_PORT__
database.url = "jdbc:postgresql://postgres:5432/__DB_NAME__"
```

### B. Kubernetes Manifests
Create standard Kubernetes Deployment and Service manifests. In the Deployment, define how the rendered configuration will be mounted.

```yaml
# k8s/components/base/new-service/deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: new-service
spec:
  template:
    spec:
      containers:
        - name: new-service
          image: mycompany/new-service:v1.0.0
          volumeMounts:
            - name: config-volume
              mountPath: /etc/new-service/config.conf
              subPath: config.conf # Mount as a single file without overwriting the directory
      volumes:
        - name: config-volume
          configMap:
            name: new-service-config # Must match the ConfigMapGenerator name
```

Add a `kustomization.yaml` inside `k8s/components/base/new-service`:
```yaml
resources:
  - deployment.yaml
  - service.yaml
commonLabels:
  component: new-service
```

## 3. Wire into the Kustomize Overlay

Next, tell the local overlay to include your new component, generate the ConfigMap from the rendered file, and apply patches.

Edit `k8s/components/overlays/local/kustomization.yaml`:

```yaml
resources:
  - ../../base/new-service

# The generator takes the rendered file (generated by Task) and wraps it in a ConfigMap
configMapGenerator:
  - name: new-service-config
    files:
      - config.conf

replacements:
  # Map the image tag
  - source:
      kind: ConfigMap
      name: global-values
      fieldPath: data.images_new_service_full
    targets:
      - select:
          kind: Deployment
          labelSelector: component=new-service
        fieldPaths:
          - spec.template.spec.containers.[name=new-service].image
```

## 4. Add the Orchestration Task

Finally, update `Taskfile.yml` to handle the rendering of your template and the deployment. See the [Taskfile Reference](../reference/taskfile.md) for more details on available global tasks.

### A. Rendering Task
Create a task to inject SSoT values into your template:

```yaml
  render:new-service:
    internal: true
    cmds:
      - |
        PORT=$(yq e '.settings.new_service.port' config.yaml)
        DB_NAME=$(yq e '.settings.new_service.db_name' config.yaml)
        
        # Inject values from config.yaml into the template
        sed -e "s/__SERVICE_PORT__/$PORT/g" \
            -e "s/__DB_NAME__/$DB_NAME/g" \
            k8s/components/base/new-service/config.conf.tpl > k8s/components/overlays/local/config.conf
```

Ensure this task is included in the global `render` workflow.

### B. Deployment Task
```yaml
  deploy:new-service:
    run: once
    deps: [init:namespace, render:new-service]
    cmds:
      - echo "🏗️  Deploying New Service..."
      - kustomize build k8s/components/overlays/local | yq 'select(.metadata.labels.component == "new-service" or .metadata.labels.component == "common")' | kubectl apply -f - --context "{{.CONTEXT}}"
```


And attach it to the main `deploy:all` task:
```yaml
  deploy:all:
    deps:
      - deploy:new-service
      # ... other deps
```

## 5. Mounting Custom Configuration Files (The Template Workflow)

If your component requires a custom configuration file (e.g., `redis.conf`, `app.properties`) that depends on values from `config.yaml`, follow this pattern:

### A. Create the Template
Place your template in the component's base directory with a `.tpl` extension. Use placeholders like `__VALUE__`.

```conf
# k8s/components/base/new-service/service-config.conf.tpl
port = __PORT__
debug_mode = __DEBUG__
```

### B. Add a Rendering Task
Update `Taskfile.yml` to render this template during the `up` or `deploy` process.

```yaml
  render:new-service:
    internal: true
    cmds:
      - |
        PORT=$(yq e '.settings.new_service.port' config.yaml)
        DEBUG=$(yq e '.settings.new_service.custom_setting' config.yaml)
        sed -e "s/__PORT__/$PORT/g" \
            -e "s/__DEBUG__/$DEBUG/g" \
            k8s/components/base/new-service/service-config.conf.tpl > k8s/components/overlays/local/new-service-config.conf
```

### C. Create the ConfigMap in Kustomize
In `k8s/components/overlays/local/kustomization.yaml`, add a `configMapGenerator` to turn the rendered file into a Kubernetes ConfigMap.

```yaml
configMapGenerator:
  - name: new-service-config
    files:
      - new-service-config.conf
```

### D. Mount the Volume in the Deployment
Finally, update your `deployment.yaml` in the base directory to mount the ConfigMap.

```yaml
# k8s/components/base/new-service/deployment.yaml
spec:
  template:
    spec:
      containers:
        - name: new-service
          volumeMounts:
            - name: config-volume
              mountPath: /etc/new-service/config.conf
              subPath: new-service-config.conf
      volumes:
        - name: config-volume
          configMap:
            name: new-service-config
```

Run `task up`, and the pipeline will automatically extract values from `config.yaml`, render the file, generate the ConfigMap, and mount it into your pod.
